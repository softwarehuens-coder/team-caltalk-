## 1. 개요

본 문서는 Team CalTalk MVP 범위(PRD 5장 Must + Should 1건)의 화면을 **저해상도(low-fidelity) 구조 와이어프레임**으로 표현한다. 각 와이어프레임은 화면에 어떤 영역과 요소(버튼/입력필드/목록)가 배치되는지를 ASCII/박스 기반 텍스트 다이어그램으로만 보여주며, 다음은 명시적으로 다루지 않는다.

- 색상, 폰트, 아이콘 선택
- 정확한 픽셀 간격/레이아웃 비율
- 최종 시각 디자인(비주얼 디자인)

이는 PRD 작성 시점에 이미 범위 밖으로 명시된 사항과 동일한 기준이며, 본 문서는 오직 **구조/레이아웃**만을 다룬다.

**대상 화면 선정 근거**: [4-project-structure.md](./4-project-structure.md) 6.1절이 이미 확정한 화면/컴포넌트 인벤토리(`features/auth`, `features/team`, `features/calendar`, `features/chat`)를 그대로 따르며, 화면 간 전환 흐름은 [3-User-scenarios.md](./3-User-scenarios.md)의 US-01~US-08을 근거로 한다. 문서에 근거가 없는 화면(설정 화면, 프로필 화면, 알림 센터 등)은 만들지 않는다.

## 3. 개별 와이어프레임

### 3.1 로그인 화면

- **화면명**: 로그인 화면
- **관련 UC/컴포넌트**: UC1(로그인/인증), `features/auth`

- **다루는 시나리오**: US-01(1단계 — 지훈 로그인), US-07(1~3단계 — 미인증 접근 차단 후 로그인 요구)

### 3.3 일정 생성/수정 폼

- **화면명**: 일정 생성/수정 폼
- **관련 UC/컴포넌트**: UC3(팀장 일정 생성/수정/삭제), `ScheduleForm.tsx`
- **등장 역할**: 팀장 전용
- **다루는 시나리오**: US-02(2단계 — "주간 정기 회의" 생성), US-06(전체 — 충돌 경고 포함 저장 흐름, 8절 오버레이 참조)

```text
+------------------------------------------------------------+
|  일정 생성                                        [ X 닫기 ] |
+------------------------------------------------------------+
|                                                              |
|  제목        [_______________________________________]      |
|                                                              |
|  시작일시    [ 2026-09-08 ] [ 14:30 ]                        |
|                                                              |
|  종료일시    [ 2026-09-08 ] [ 15:30 ]                        |
|                                                              |
|  참여자      [ ] 지훈(팀장)                                   |
|              [x] 서연(팀원)                                   |
|              [x] 민준(팀원)                                   |
|                                                              |
|  ( 충돌 경고 배너 영역 — 저장 시도 시에만 표시,                |
|    상세는 8절 참조. 평소에는 빈 상태 )                        |
|                                                              |
|              [ 삭제 ]   [ 취소 ]   [   저장   ]               |
|                                                              |
+------------------------------------------------------------+
```

**참고**: 필드 구성은 [7-erd.md](./7-erd.md) `SCHEDULE`(title, start_at, end_at) + `SCHEDULE_PARTICIPANT` 관계를 근거로 한다. `[ 삭제 ]` 버튼은 기존 일정 수정 진입 시에만 노출되고, 신규 생성 시에는 노출되지 않는다.

### 3.4 일정 상세 + 채팅 패널

- **화면명**: 일정 상세 + 채팅 패널
- **관련 UC/컴포넌트**: UC5(캘린더-채팅 연동 조율), UC8(일정별 채팅 이력 확인), `ScheduleChatPanel.tsx`
- **등장 역할**: 공통(채팅 작성/열람은 팀장·팀원 모두 가능, 4장)
- **다루는 시나리오**: US-03(2~5단계 — 조율 채팅), US-05(6단계 — 거절·재요청·승인 전체 이력), US-08(3~4단계 — 과거 채팅 이력 확인)

```text
+------------------------------------------------------------------+
| < 캘린더로 돌아가기                                                |
+------------------------------------------------+-----------------+
| 일정 상세                                        | 채팅            |
|                                                  |                 |
| 제목: 주간 정기 회의                              | ( 이전 메시지    |
| 시작: 2026-09-08 14:00                          |   더 보기 )      |

| 참여자: 지훈(팀장), 서연(팀원), 민준(팀원)          | 서연 14:02       |
|                                                  | 오후에 다른 미팅  |
| (팀원 전용) [ 변경 요청하기 ] → 3.5 참조           | 있어 30분 정도   |
|                                                  | 늦을 수도...     |
| (팀장 전용, 대기중 요청 있을 시)                   |-----------------|
|   [ 변경 요청 검토 ] → 3.6 참조                    | 지훈 14:05       |
|                                                  | 네, 늦으셔도     |
|                                                  | 괜찮습니다       |
|                                                  |-----------------|
|                                                  | ( 메시지 계속... )|
|                                                  |-----------------|
|                                                  | [___________]   |
|                                                  |     [ 전송 ]     |
+------------------------------------------------+-----------------+
```

**참고**: "이전 메시지 더 보기"는 [4-project-structure.md](./4-project-structure.md) 5.4절이 명시한 채팅 이력 페이지네이션 조회(REST, UC8)를 화면 요소로 반영한 것이며, 메시지 입력창과 실시간 송수신은 WebSocket 경로(UC5)를 반영한다.

```text
|              [   승인   ]      [   거절   ]                  |
|                                                              |
|  --- [ 거절 ] 클릭 시에만 아래 영역 노출 ---                   |
|                                                              |
|  거절 사유 (필수)                                             |
|  [________________________________________________]         |
|                                                              |
|              [ 취소 ]      [   거절 확정   ]                  |
|                                                              |
+------------------------------------------------------------+
```

**참고**: 승인 시에만 일정이 즉시 갱신되며(SC3), 거절 시 사유 입력이 필수이고 채팅을 통해 요청자에게 통지된다(US-05 2~3단계). 이 UI는 3.4 채팅 패널 내 `[ 변경 요청 검토 ]`에서 진입한다.

### 3.7 팀 관리 화면

- **화면명**: 팀 관리 화면
- **관련 UC/컴포넌트**: 팀 라이프사이클(도메인 정의서 5장 — 생성/초대·가입/탈퇴/팀장 위임), `features/team`
- **등장 역할**: 공통(초대/위임 등 일부 요소는 팀장 전용으로 분기)
- **다루는 시나리오**: US-01(전체 — 팀 생성, 초대, 가입, 구성원 확인)

```text
+------------------------------------------------------------------+
| < 캘린더로 돌아가기            팀 관리 — 디자인팀                  |
+------------------------------------------------------------------+
|                                                                    |
|  (팀이 없는 사용자에게만 노출)                                     |
|  [ 새 팀 만들기 ]   팀 이름 [_____________________] [ 생성 ]       |
|                                                                    |
|--------------------------------------------------------------------|
|  구성원 목록                                                       |
|                                                                    |
|   이름       역할        상태                                      |
|   지훈       팀장        -                                         |
|   서연       팀원        (팀장 전용) [ 팀장 위임 ]                  |
|   민준       팀원        (팀장 전용) [ 팀장 위임 ]                  |
|                                                                    |
|--------------------------------------------------------------------|
|  (팀장 전용) 팀원 초대                                             |
|  이메일 [___________________________]  [ 초대 보내기 ]              |
|                                                                    |
|--------------------------------------------------------------------|
|  (본인 행에만 노출) [ 팀 탈퇴 ]                                     |
|                                                                    |
+------------------------------------------------------------------+
```

**참고**: 구성원 목록의 역할 표기(팀장/팀원)는 4장 권한 SSOT를 근거로 한다. `[ 팀장 위임 ]`은 팀장 본인 화면에서만 다른 팀원 행에 노출되고, `[ 팀 탈퇴 ]`는 본인 행에만 노출된다. 팀 해체(유일 팀장이 위임 없이 탈퇴 시도하는 경우의 처리)는 도메인 정의서 5장에 규정되어 있으나, 그 정확한 확인/경고 문구는 근거 문서에 UI 문구까지 명시되어 있지 않아 별도 확인 모달의 존재만 구조적으로 남겨두고 세부 문구는 다루지 않는다.

### 3.8 일정 충돌 경고 배너 (Should, #3 오버레이)

- **화면명**: 일정 충돌 경고 배너 — 3.3 "일정 생성/수정 폼" 내부에 나타나는 오버레이/인라인 요소이며 별도 화면이 아님
- **관련 UC/컴포넌트**: UC9(일정 충돌 감지/경고), `ScheduleConflictBanner.tsx`
- **등장 역할**: 팀장 전용
- **다루는 시나리오**: US-06(전체 — 저장 시점 경고, 경고 확인 후 그대로 저장 또는 시간 수정 후 재저장)

```text
+------------------------------------------------------------+
|  일정 생성                                        [ X 닫기 ] |
+------------------------------------------------------------+
|  제목        [ 내부 워크숍                            ]      |
|  시작일시    [ 2026-09-08 ] [ 14:30 ]                        |
|  종료일시    [ 2026-09-08 ] [ 15:30 ]                        |
|  참여자      [x] 서연(팀원)   [x] 민준(팀원)                  |
|                                                              |
|  +--------------------------------------------------------+ |
|  | ! 일정 충돌 경고                                         | |
|  |   서연(팀원)의 기존 일정 "고객사 미팅"                     | |
|  |   (2026-09-08 14:00~15:00)과 시간이 겹칩니다.             | |
|  |   저장은 차단되지 않으며, 참고 후 그대로 진행할 수 있습니다. | |
|  +--------------------------------------------------------+ |
|                                                              |
|              [ 삭제 ]   [ 취소 ]   [ 그대로 저장 ]            |
|                                                              |
+------------------------------------------------------------+
```

**참고**: 경고는 저장 시도 시점에 나타나는 참고 정보이며 저장 자체를 차단하지 않는다(SC4). 시간이 겹치지 않도록 값을 수정한 뒤 다시 저장을 시도하면 배너 없이 저장이 완료된다(US-06 5~6단계).

## 4. 커버리지 확인

MVP Must 범위(UC1-UC8 + 팀 라이프사이클)와 Should 1건(UC9)이 와이어프레임에서 모두 다루어졌는지 자체 점검한다.

| # | 와이어프레임 | 커버하는 UC | 커버하는 US |
|---|---|---|---|
| 3.1 | 로그인 화면 | UC1 | US-01, US-07 |
| 3.2 | 캘린더 화면(팀장/팀원 뷰) | UC2, UC3(진입점), UC4 | US-02, US-03, US-07, US-08 |
| 3.3 | 일정 생성/수정 폼 | UC3 | US-02, US-06 |
| 3.4 | 일정 상세 + 채팅 패널 | UC5, UC8 | US-03, US-05, US-08 |
| 3.5 | 변경 요청 작성 폼 | UC6 | US-04, US-05 |
| 3.6 | 변경 요청 승인/거절 UI | UC7 | US-04, US-05 |
| 3.7 | 팀 관리 화면 | 팀 라이프사이클(도메인 정의서 5장) | US-01 |
| 3.8 | 일정 충돌 경고 배너(오버레이) | UC9 | US-06 |

모든 Must 항목(UC1-UC8, 팀 라이프사이클)과 Should 항목(UC9)이 최소 1개 와이어프레임에서 다루어졌다. 근거 문서에 없는 화면(설정, 프로필, 알림 센터 등)은 포함하지 않았다.
